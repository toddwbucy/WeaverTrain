## What the checks found

1. **Short answers again.** In round 1, 258 texts were missing from grouped answers that
   stopped early (the first batch: 236). Round 2 asked for them again.
2. **A new server error.** In round 2, 11 of 73 requests came back with
   `Precondition check failed` (code 9) and no output. Their texts went to round 3 with
   the other failures, and all came back. It did not repeat.
3. **Glued literals are not repaired.** 17 segments in 8 trajectories passed the STE
   checker but changed a literal glued to a placeholder: `[[C1]]-related` rewritten,
   `[[C19]]s` or `[[C14]]'s` dropped, `Pop![[C9]]` altered. Assembly refuses those, as it
   should. But the repair rounds only send checker failures back, so these never got a
   second try. That is why 8 of the 9 failed trajectories failed. The ninth (T112) has
   one ordinary checker failure. The first batch did not hit this. Some of these
   (a dropped possessive on a code name) are arguably fine STE, so the check may also be
   stricter than it needs to be. Fixing either is a code change to `judge_round` or
   `glued_literals`, not made.
4. **Integrity of the 191 converted rows**, checked against the dataset rows: only the
   agent's own messages changed (6,437), tool calls other than `finish` and all other
   source fields are unchanged. The `ste` field records provenance. In `finish`,
   the `message` argument has new text. Other arguments stay equal as JSON values,
   but the spaces and the escape sequences for characters can change. No `[[Cn]]`
   placeholder is left.
   No row has a tag that the original did not have, and every row is at or under 32,768 tokens.

No meaning review was run on this batch. The first batch's sample was 90 faithful, 9
minor, 0 wrong.
